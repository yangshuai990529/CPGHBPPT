# AI Picture Analysis
Version: 1.1.0

## Purpose
Separate the picture-processing chain from AI marketing language and user-value hypotheses.

## When to Use
A TV or AI TV brief asks what an AI picture feature does or whether users can understand and control its effect.

## When NOT to Use
Do not use one official feature list as proof of measured picture quality, user preference learning or full AI-agent autonomy.

## Input
Model, market, signal/content, picture mode, source passages, settings interaction, test conditions and Evidence IDs.

## Reasoning Process
Trace content/environment input → detection/recognition → processing → parameter/output change → user explanation/control → feedback. Label each link `vendor claim`, `observed result`, `interpretation` or `unknown`. Check whether behavior is automatic, user-triggered or a fixed preset. Compare only shared links and record firmware/market variation.

## Output
A scoped capability chain and gaps, followed by questions for Product Reasoning. No unsupported product opportunity or strategy.

## Output Schema
Use `schemas/evidence.schema.json` and `schemas/claim.schema.json`; inferences follow `schemas/insight.schema.json` and cite Evidence IDs.

## Quality Criteria
Claims identify the exact link in the chain, with source and scope. Personalization is not marked supported merely because preferences can be selected.

## Common Mistakes
Do not collapse scene recognition, auto picture adjustment and preference learning into one `AI Picture ✓` cell.

## Example
A vendor page says color changes per scene: mark scene-conditioned adjustment for that page. Leave environment sensing and long-term learning unknown until independently evidenced.
