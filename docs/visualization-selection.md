# Visualization Selection

先识别内容意图和数据结构，再选择图。视觉类型不是模板；只有当逻辑关系成立时才使用。

| 类型 | 适用 | 不适用 | 最小输入 |
| --- | --- | --- | --- |
| Big Number | 一个需被强调且有上下文的核心数字 | 多指标对比、没有来源或基准 | 数值、单位、口径、时间、Source |
| Bar Chart | 离散类别之间比较 | 连续时间趋势、类别过多且标签不可读 | 类别、数值、统一单位 |
| Line Chart | 连续时间变化、趋势和拐点 | 少量无序类别、只有一个时间点 | 时间序列、单位、缺失值规则 |
| Funnel | 明确定义的逐级转化和流失 | 只是流程步骤、分母不一致 | 每级人数/比例和口径 |
| Comparison Matrix | 多个对象按同一维度比较 | 维度定义不一致、仅罗列功能 | 对象、维度、评分/事实规则 |
| Feature Table | 需要精确查询和逐项核对 | 目标是表达结论或总体定位 | 统一字段、来源、例外说明 |
| 2×2 Matrix | 两个独立且可解释的维度形成定位 | 维度随意、坐标无依据、第三维决定结果 | 轴定义、标度、对象位置依据 |
| Radar | 少量对象在同尺度多维画像 | 需要精确比较、尺度不同、维度过多 | 3 至 8 个同尺度维度 |
| Pyramid | 稳定的层级、优先级或递进关系 | 普通列表、时间流程 | 层级定义和上下关系 |
| Strategy House | Goal、Strategic Pillars、Foundation 三层关系 | 只有目标和任务清单、支柱不独立 | 目标、支柱、基础能力 |
| Journey Map | 用户按阶段经历行为、触点、痛点和机会 | 系统流程或技术架构 | 阶段、行为、触点、痛点、机会 |
| Architecture | 明确的分层、模块或依赖关系 | 任意功能堆叠、没有层间关系 | 层级、模块、接口/依赖 |
| Roadmap | 阶段目标、能力演进和依赖 | 单纯日历、无阶段逻辑 | 阶段、目标、交付、依赖、指标 |
| Timeline | 事件按时间顺序解释变化 | 比较类别、阶段没有日期意义 | 时间点、事件、因果/里程碑 |

## 选择流程

1. 先写要让读者理解的关系：大小、变化、组成、转化、定位、层级、流程、依赖或阶段。
2. 检查数据是否支持该关系。缺数据时保留为候选，不绘制虚构占位数据。
3. 比较候选图的认知成本，选择最简单且不丢失关键信息的一种。
4. 在 Slide Spec 的 `visualization.reason` 写明选择依据，并记录被拒绝的高风险替代方案。
5. 若文本或一张真实截图更清楚，允许 `type: text` 或 `type: image`。

## 通用禁用条件

- 视觉形式会暗示不存在的精确度、比例或因果关系。
- 图形需要读者在不同尺度之间比较。
- 图中对象、维度或时间口径不一致。
- 视觉结构只是为了填满版面。
- 内容可用一句结论和两条证据更清楚地表达。
